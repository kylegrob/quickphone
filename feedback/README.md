# Feedback

One file per sprint (`sprint-1.md`, `sprint-2.md`, …) holding everything the professor, GA or client said about that sprint's work, plus what we did about it. Copy [_template.md](_template.md) to start a new sprint.

**Paste feedback verbatim.** Rubric comments, the grade, emailed notes and in-class remarks all go in as written, with date and source. Paraphrase only in the action items, and keep each action item short enough to tick off.

**Close the loop.** When an action item is done, tick it and name the deliverable and version that fixed it. The Change Log then records the change itself (what changed, why, effect on later deliverables). The professor checks that earlier feedback was carried forward, so an open item here is a risk for the next submission.

**Client feedback** goes in the same sprint file under its own heading. Anything the client *confirms* also goes into [docs/project-context.md](../docs/project-context.md), since that is where the requirements are read from.

AI assistants read this folder before editing any deliverable (see [AGENTS.md](../AGENTS.md)). To hand feedback to an assistant, paste it into the sprint file and ask it to work through the open action items.
